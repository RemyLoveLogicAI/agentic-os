## Overview

The services directory is the top-level location for service implementations in this repository. At the root of this directory there are no standalone files; instead, service implementations are organized into subdirectories. The only listed subdirectory is loop-harness/, which contains the TypeScript implementation, public API surface, and tests for the loop-harness service, along with filesystem-backed utilities, lifecycle helpers, and CLI/daemon entry points. The implementation is organized under a src/ area inside that subdirectory and includes core type definitions and configuration handling (e.g., types.ts and config-related files referenced in the subdirectory description).

Together, the components in services provide self-contained service modules that include implementation code, public APIs, utilities for interacting with the filesystem, lifecycle helpers used to start/stop or otherwise manage the service, and both CLI and daemon entry points for running the service. Tests for the service are colocated with its implementation to make it straightforward to validate behavior. This directory plays the role of grouping service-level code so that each service can be developed, tested, and invoked independently while exposing a clear public API and runtime entry points (CLI/daemon) for the larger system to consume.
